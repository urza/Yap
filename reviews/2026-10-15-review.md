# Yap-r2 code and browser review

The app builds and its basic chat flows work. The review confirms **12 bugs**, including private-message disclosure and incorrect account identity across tabs. Fix the privacy and account issues before deployment.

Reviewed checkout: `3cbdf5ed8632fb5d6f0df162be0bcdf3c2525155`, on 2026-10-15. Requirements come from `docs/refactor-prompt-2026-10-14.md`, `docs/spec`, and the offline design notes. This is a review of the current rewrite, not a claim that every issue first appeared in that commit.

The application source was not changed. The existing deletions under `Yap.Tests/` and modification to `Yap.slnx` were preserved.

### F01. Check reply authorization before resolving the original message

Source: [MessageMapper.cs:47](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Services/Chat/MessageMapper.cs:47), and the send validation in [ChatService.cs:383](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Services/Chat/ChatService.cs:383).

Create a DM between A and B. Send a private message. As C, POST a lobby message with that private message's ID as `replyToId`. The endpoint returns HTTP 200 with the original DM text in `replyTo.text`. The lobby also displays that quote.

The test first checks the direct history endpoint: C gets zero DM messages. The crafted reply then returns `PRIVATE DM SENTINEL`. Thus the normal history authorization does not protect the reply path.

`ReplyTo()` resolves the ID globally. Neither the sender nor the mapper checks that the original belongs to the destination conversation. The exploit requires a known message ID; random IDs are not demonstrated to be guessable. History cutoffs also need consideration when showing quotes to different room readers.

Reject replies to another conversation, and apply the intended history visibility rules. This violates GEN-04. Evidence: `review.log`, test `DM quote authorization`.

### F02. Propagate account transitions to every tab on the device

Source: [session.js:28](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/session.js:28), [session.js:40](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/session.js:40), and [SignInEndpoints.cs:29](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Endpoints/SignInEndpoints.cs:29).

Two reproductions show the same missing device-wide transition:

- Open two tabs as A. Sign out in the first. The second keeps A's live SignalR connection and receives a new private message. Its bootstrap response is anonymous, but its client still reports A and `connected`.
- Open two tabs as A. Use B's login link to switch the first tab to B. The second still displays A. Send from that tab: the server records the message as B, because both tabs now share B's cookie.

The cleanup only changes the initiating tab. The shared outbox broadcasts storage changes, but it does not synchronize account identity. Existing hub connections retain their original authenticated principal.

Coordinate sign-out and account switches across tabs. Stop old connections and pending work before another account can send. Ensure device sign-out also closes that device's other server connections. This violates GEN-05, AU-22, and AU-25. Evidence: `review.log` and `review3-repeat.log`.

### F03. Do not join disconnected history ranges as if they were contiguous

Source: [store.js:62](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/store.js:62).

Load a room containing one message. Disconnect that browser. Send 60 messages from another browser, then reconnect the first browser.

The first browser shows 51 messages: its old message plus the newest 50. Messages `gap-1` through `gap-10` are missing. `hasMore` is false, so scrolling cannot retrieve them. The missing messages still exist on the server.

`setOpen()` prepends the retained old range and replaces the server's `hasMore` with the previous value. Even with `hasMore=true`, pagination from the oldest retained row cannot fill a gap after that row.

Keep a valid pagination boundary or replace the disconnected range with the server tail. This violates TL-35. Evidence: `review2.log`, test `Reconnect after more than one page`.

### F04. Reattach both pickers when reusing the phone sheet

Source: [composer.js:259](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/ui/composer.js:259) and [composer.js:328](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/ui/composer.js:328).

At a 390 px viewport, open the emoji sheet. Go to Settings, return to chat, and open the sheet again. Its tabs remain, but both panes are empty. The test counts 1,000 emoji buttons before navigation and zero afterward.

Composer teardown removes the emoji element, GIF element, and combined sheet separately. The next mount reuses the sheet, but only its first creation appends those children.

Reattach the child pickers on each phone layout, or preserve their parent-child structure during teardown. Check the same behavior when crossing the 600 px breakpoint. This violates IB-41 and the picker continuity rules. Evidence: `review.log` and [phone screenshot](2026-10-15-evidence/phone-picker-after-navigation.png).

### F05. Identify the lobby independently of sidebar order

Source: [chat.js:70](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/pages/chat.js:70), [frame.js:208](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/ui/frame.js:208), and [Conversation.cs:14](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Models/Chat/Conversation.cs:14).

Create `firstroom`, move it above the lobby with the supported room-order control, then open `/lobby`. The client opens `firstroom`. The test records different IDs for the actual lobby and the opened conversation.

The client uses `state.rooms[0]` as the lobby throughout navigation, lobby presence lines, and channel settings. The backend permits reordering the actual lobby and does not include `IsDefault` in `RoomDto`.

Send the real lobby identity in the contract and use it throughout the client. Sidebar ordering must not change a conversation's URL identity. This conflicts with SH-43 and AD-33. Evidence: `review.log`, test `Room reorder changes lobby destination`.

### F06. Persist `ClientId` in the detached message copy

Source: [Writes.cs:155](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Services/Persistence/Writes.cs:155).

With SQLite enabled, POST a message with a client UUID. Stop the server cleanly, restart it, and repeat the exact POST with the same cookie and UUID.

Both requests return HTTP 200, but their message IDs differ. SQLite contains two copies. Before restart, the original database row already has `ClientId=NULL`.

`Detached()` copies the message ID and edited flag but omits `ClientId`. Startup therefore cannot rebuild the retry dictionary from stored messages.

Copy `ClientId` into the persisted entity. Test a retry across restart, not only two POSTs within one process. This contradicts the offline design's deduplication contract. Evidence: `persistence.log`.

### F07. Keep every GIF from a file selection

Source: [sender.js:119](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/sender.js:119), and the single-GIF request shape in [MessagesEndpoints.cs:55](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Endpoints/MessagesEndpoints.cs:55).

Select two valid GIF files in one attachment pick. Both uploads complete. The resulting message has one GIF, with no failed row or warning.

The upload loop assigns every GIF to the same `row.gif` field. Each assignment replaces the previous attachment. The POST contract also accepts only one GIF.

Represent uploaded GIFs as a collection through the outbox and send contract. This violates IB-32 and IB-33. Evidence: `review2.log`, test `Multi GIF pick retains all attachments`.

### F08. Include chosen Away in automatic read decisions

Source: [timeline.js:231](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/ui/timeline.js:231), with the same omission on page exit in [chat.js:57](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/pages/chat.js:57).

Choose Away while a DM is visible and scrolled to the bottom. Send a message from the other participant. The account stays Away, but its unread count becomes zero.

The client equates “not away” with less than 300 seconds since local input. It does not check the chosen account status. This also disregards activity on other devices when considering automatic Away.

Use the account's effective Away state for automatic read decisions. Opening a conversation should still follow the separate NT-06 rule. The reproduced behavior violates NT-07 and PR-24. Evidence: `review2.log`.

### F09. Give unopened offline DMs an outbox destination

Source: [chat.js:81](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/pages/chat.js:81).

Sign in while online, then disconnect. Open a known person's DM that this device never opened. Type and press Send.

The text remains in the input, `state.open` remains null, and there is no pending message. A reload cannot restore this as a queued send. The room path has an offline fallback; the DM path has none without a stored tail.

Allow a pending DM destination to be represented by its partner, then resolve its channel on reconnect. This violates OF-08, which explicitly includes conversations never opened on the device. Evidence: `review2.log`.

### F10. Do not claim sign-out succeeded when the cookie remains valid

Source: [session.js:60](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/wwwroot/js/session.js:60).

Disconnect the browser, sign out, restore the network, and reload. The app returns to the same authenticated account.

`signOut()` swallows a failed POST and calls local cleanup. Its comment says the cookie disappears either way, but the HttpOnly cookie can only be cleared by the server response.

Show a connection requirement, or persist a pending sign-out and complete it before restoring an authenticated session. This violates AU-22. Evidence: `review.log`, test `Offline signout then reconnect`.

### F11. Respect explicit sign-out on the installed app's start URL

Source: [PwaEndpoints.cs:59](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Endpoints/PwaEndpoints.cs:59) and [SignInEndpoints.cs:29](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Endpoints/SignInEndpoints.cs:29).

Get the authenticated manifest's `start_url`, sign out successfully, then navigate to that URL. The app signs into the previous account again.

The handoff token remains usable for 72 hours. Sign-out clears the cookie but records nothing that stops this device from redeeming the saved token again.

Remember explicit device sign-out when processing PWA handoffs. This test exercises the actual launch URL; it does not require a physical phone installation. The behavior violates AU-22's explicit PWA requirement. Evidence: `review2.log`.

### F12. Authorize typing updates against the destination conversation

Source: [ChatHub.cs:92](/d/PROJECTS/d3mnjx/repos/urza/Yap-r2/Yap/Endpoints/ChatHub.cs:92).

As C, invoke `Typing(dmBetweenAAndB, true)` using a known DM channel ID. B sees C in that private conversation's typing strip. The test records `revieweve` in B's DM typists.

The hub forwards the supplied channel ID without checking access. PresenceService accepts it, and the broadcaster routes the event to the DM participants.

Verify access before accepting a typing update, preferably against the connection's current conversation. This violates PR-19. It is an integrity defect; this test does not show that typing reveals DM text. Evidence: `review.log`.

The basic tests cover sign-in, live delivery between two users, reactions, edits, deletion, typing, DM navigation, and unread counters. They also cover image uploads and gallery behavior, replies, history paging, basic phone layout, settings, administration, and room management. The offline suite confirms cached reload, queued text and image sends, reconnect, and same-process retry deduplication.

The first smoke run reported 16 passes and one failure. Its navigation assertion waits for the URL, then immediately checks the page context. The repeat passed all 17 steps. That timing-sensitive assertion is not counted as a confirmed application bug.

The deleted server test files were copied from Git HEAD into `/tmp` for execution. They were not restored in the checkout. Initial server-test attempts failed because the container ran out of disk space. A successful run used a temporary directory on `/dev/shm` and excluded optional media executables from PATH. These server tests do not validate media processing. The browser and SQLite reproductions ran earlier with normal media-tool access.

Build warnings include two moderate ImageSharp advisory IDs: `GHSA-gwg2-r3hj-4w44` and `GHSA-wmxv-xphr-5c9g`. The package also suppresses NU1903 warnings. Dependency remediation needs a separate check; this review does not claim to reproduce those vulnerabilities.

## Scope and limits

Tests used disposable accounts, isolated content roots, and a copied web root. The repository's data and uploads were not used as writable test storage. Linux build outputs were removed afterward to avoid mixing Windows and Linux `bin`/`obj` files.

The environment used .NET SDK 10.0.401 and runtime 10.0.12. Playwright 1.47.2 drove an already-installed Chromium because downloading its pinned browser ran out of space. Tests ran on loopback HTTP, where Chromium permits secure browser APIs.

Real Web Push delivery, physical iOS/Android installation, configured Klipy search, external video-site extraction, and production proxy/TLS deployment were not validated. Neither a production database migration nor sustained load was tested. The standalone SQLite restart test used a new database.

The backend uses ASP.NET Core endpoints and SignalR. The production client uses static JavaScript modules. The inspected build and Docker paths do not require npm or Node, and the startup/client paths contain no Blazor runtime.

These findings are specific mismatches between the rewrite and its stated requirements. The review does not attempt a complete pixel-by-pixel comparison or certify every specification rule.
