Offline and installation

Yap runs in the browser and can be installed on a phone or a desktop like an app. Without a connection it stays readable and keeps what the user writes. This page decides what the installed app is, what works without a connection, and what happens to messages written offline. The design behind it is in docs/offline-design-notes.md; the promise here is deliberately modest. Yap is not a critical system. A message lost once in a long while is acceptable; a second of lag on every tap is not.

Rules

Installation

OF-01Yap can be installed from the bot's welcome message ("install it"), from Settings ("Install Yap"), or from the browser's own install control. The install dialog explains how to replace an older install before it starts the browser's install or shows the add-to-home-screen guide. When Yap is already installed, the dialog says so.

OF-02The installed app opens full screen, with the Yap icon, name and colours. It starts on the user's last conversation, else the lobby.

OF-03The installed app signs in by itself on its first launch when it was installed from a signed-in browser. Afterwards it keeps its own session like any device.

OF-04A new version of Yap is announced in the notice strip with "Reload". Yap never reloads by itself, and a reload keeps drafts and unsent messages.

Without a connection

OF-05The header shows the state: a grey ring while offline, a pulsing orange dot while reconnecting. No banner covers the content.

OF-06Every conversation the user has opened on this device shows its last messages and can be read and scrolled. Older messages that were not loaded say "Needs a connection" at the top of the list. Media that was seen before shows; media that was not says so in its place.

OF-07Typing, drafts, emoji, the emoji picker, the GIF picker's own lists, switching conversations and reading all work without a connection.

OF-08Sending works without a connection. Send accepts the message, shows it as pending in the conversation, and keeps it on the device. It is sent when the connection returns, also after the app was closed and reopened.

OF-09A message with attachments is accepted without a connection up to 25 MB in total. Above that, Send does nothing and the input box says "needs a connection".

OF-10Pending messages are sent in the order they were written, as soon as a connection exists. The user sees each one turn into a normal message. No action is needed.

OF-11A pending message that the server refuses shows as failed, with the reason, "Retry" and "Remove". A pending message that has waited more than one day shows as failed too. Remove deletes it from the device only.

OF-12Reactions, edits, deletions, status changes, GIF search and trending need a connection. Where the user tries them, the answer is "Needs a connection" and nothing changes.

OF-13Reconnecting is automatic: when the network returns, when the tab comes back, and when the user taps the connection dot. The newest messages are refreshed and the unread counts corrected; the view keeps its place.

The promise and its limits

OF-14Offline reading shows what the device already had. It does not download conversations ahead of time beyond the ones the user opened.

OF-15Sending later is best effort. A message can be lost when the device loses its storage, when the account changes, or when the server has restarted without its accounts. The user is told through the failed state, never silently.

OF-16Signing out, or a different account signing in on the device, removes every draft, pending message and cached conversation of the previous account.
