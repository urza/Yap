# Spec screenshots

The images in `docs/spec/img/` are generated by the scripts in this folder. They are never edited by hand: no cropping, no arrows, no retouching. To change an image, change its state in `capture.mjs` (or the data in `seed.mjs`) and capture again. A screenshot that no longer matches its page is a bug in one of the two.

| File | Job |
| --- | --- |
| `seed.mjs` | Fills a fresh instance with the accounts and messages the images show. |
| `capture.mjs` | The list of named states. Drives the page into each state and writes the PNG. |
| `common.mjs` | Shared parts: arguments, devices, sign-in, waits. |

## What you need

- Node 22 (the scripts use `node:sqlite` to read login tokens; no other database tool).
- Playwright with Chromium. The repository root pins it: `npm ci --ignore-scripts --no-audit --no-fund`, then `node node_modules/playwright/cli.js install chromium`. To use another install, set `PLAYWRIGHT_MODULE=/absolute/path/to/playwright`, as for the browser tests.
- The .NET SDK that builds the app.

## 1. Publish and run the app

The visual target is the page at commit `0cb67422`. Build it outside this working tree: the tree is also built from Windows, and mixed-OS `bin/` and `obj/` folders break its styles.

```sh
WORK=/tmp/yap-spec                       # any folder outside the repository
mkdir -p "$WORK/src"
git -C /path/to/Yap archive 0cb67422 | tar -x -C "$WORK/src"
dotnet publish "$WORK/src/Yap/Yap.csproj" -c Release -o "$WORK/app"

cd "$WORK/app"
ASPNETCORE_ENVIRONMENT=Development dotnet Yap.dll --urls http://127.0.0.1:7651
```

`ASPNETCORE_ENVIRONMENT=Development` is necessary. Without it the static files fail and the page never starts.

The app keeps its data inside `$WORK/app`: the database and settings in `Data/` (the database is `Data/yap.db`), uploaded files in `wwwroot/uploads/`. For a fresh start, stop the app, delete `Data/yap.db*` and `wwwroot/uploads/*`, and start it again.

Stop the app by its process ID (`kill <pid>`). Do not use `pkill -f`: a pattern that matches `dotnet Yap.dll` also matches the shell that runs the command.

## 2. Seed

```sh
node docs/spec/tools/screenshots/seed.mjs --origin http://127.0.0.1:7651 --db "$WORK/app/Data/yap.db"
```

On a fresh instance, registration is open, so a new name at `/auth/signin?username=<name>` creates the account. The seed creates `alice` and `bob` that way and then uses the real page, like a user, to write:

- about 30 messages between them in `#lobby`, with a few emoji, one image, one reply and one reaction;
- a direct message thread of six messages.

It then waits with the bot conversation open until the bot's welcome message arrives (the bot sends it one minute after sign-up). That keeps unread badges out of the images. The seed takes a little over one minute.

The seed runs once. If `alice` or `bob` already exists, it does nothing.

## 3. Capture

```sh
node docs/spec/tools/screenshots/capture.mjs --origin http://127.0.0.1:7651 --db "$WORK/app/Data/yap.db"
node docs/spec/tools/screenshots/capture.mjs --origin http://127.0.0.1:7651 --db "$WORK/app/Data/yap.db" input-box-phone-sheet
```

With no names, every state is captured. A state name is `<page>-<device>-<state>` and is also the file name in `docs/spec/img/`. The script signs in with the account's token from the database (`/auth/refresh-token?token=...`), so it creates nothing and changes no data.

`--origin` and `--db` can also come from `YAP_ORIGIN` and `YAP_DB`.

| State | What it shows |
| --- | --- |
| `input-box-desktop-empty` | alice in `#lobby`, empty draft: room placeholder, GIF badge, grey emoji icon, Send hidden. |
| `input-box-desktop-text` | The draft reads "hello": Send shown, the GIF toggle collapsed. The light theme of this page draws no glow on Send. |
| `input-box-phone-sheet` | Phone, emoji sheet open from the emoji toggle over an empty draft. The whole screen. |

Devices: `desktop` is 1280 × 800. `phone` is 390 × 844 with touch, at device scale factor 2. All captures use the light theme ("Daylight"), set with the page's own theme switch. The app's default theme is dark.

A desktop input box image is the conversation column from about 260 px above the bottom of the window. The top edge moves up to the gap above a message row, so no row is cut.

## Adding a state

Add an entry to `STATES` in `capture.mjs`: the page prefix, the device, a state name and an async `drive(page)` function. `drive` brings the page into the state and returns the clip rectangle, or `null` for the whole screen. Make `drive` fail when the page is not in the state the image claims to show (see `expectWidth`), so a changed page does not silently produce a wrong image.

## Differences between two captures

Some parts change from one capture to the next. This is expected:

- The room placeholder and the emoji toggle's emoji are picked at random by the server each time the page opens.
- Message times are the times of the seed run.
